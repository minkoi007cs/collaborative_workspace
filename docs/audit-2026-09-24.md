# SyncSpace audit — 2026-09-24

## Scope and evidence

Reviewed the API controllers/services, authorization paths, Socket.IO gateway, Next.js routes and middleware, public/auth screens, dependency graph, project history, and existing tests. Exercised the public landing and login screens in a local browser. Ran `pnpm check`, `pnpm test:integration`, `pnpm build`, and `pnpm audit --prod --audit-level high` after the fixes. Integration tests use local PostgreSQL/Redis, signed test JWTs, and a storage mock. No Supabase credentials or private bucket were available for a signed-in browser session.

## Findings addressed

| Priority | Finding | Impact and resolution |
| --- | --- | --- |
| High | A socket retained its previous `task:{id}` room after navigating to another board or leaving it. | It could still receive events for a task no longer in view. | High | A viewer could emit typing indicators despite lacking permission to comment. | Active typing now requires current editor access to the task board. A viewer rejection is covered by integration test. |
| Medium | An invitation destination cookie survived a normal visit to login/signup. | A later sign-in could unexpectedly send the user back to an old invitation. Middleware now clears it unless the current request contains a validated invitation path; unit test covers the transition. |
| Medium | The public landing page still described workspaces as in development. | Rebuilt the page around the implemented workspace, board, task, presence, file, and notification flows. Signup actions only appear when Supabase is configured; the unavailable state is explicit. |
| High | Production audit reported 9 transitive advisories, including 6 high severity. | Pinned patched PostCSS 8.5.28, Multer 2.4.0, and deepmerge-ts 8.0.0 through root pnpm overrides. Install, tests, Prisma-backed integration, builds, and production audit pass. Revisit overrides when upstream Next/Nest/Prisma update their own dependency ranges. |
| Medium | Concurrent upload reservations could exceed the 20-file task quota. | A transaction now locks the task row before counting all pending and ready attachments. A 21-request integration race confirms exactly 20 reservations succeed. |

## Product direction

Position SyncSpace as a focused shared planning board for small teams. The clearest journey is: create a workspace → invite a teammate → plan tasks on a board → discuss and move them together. Keep that journey prominent in navigation and onboarding. Prioritize reliable invitations, live two-user QA, and deployment operations over optional collaborative notes or analytics. Treat presence as context and task data in PostgreSQL as the source of truth.

## Open risks and release gate

1. **External configuration:** Supabase Auth credentials, Google provider setup, private bucket policy, CORS, and deployment secrets are absent. This prevents a valid claim of end-to-end product readiness.
2. **Attachment reconciliation:** abandoned pending rows consume quota, and failed storage cleanup can leave orphaned objects. Add expiry and a reconciliation worker before exposing uploads at scale.
3. **Delivery gaps:** notifications and activity publication can be missed after a successful mutation, and socket events have no durable replay. Reconnect refresh covers many cases but cannot guarantee every transient delivery.
4. **Coverage:** authenticated page visuals, mobile layout, Google OAuth, real storage, and production ingress were not exercised. Current integration tests prove local API behavior, not those external flows.
